# Задачник для торговых агентов — краткая справка для нового диалога

Дата: 2026-08-26. Это сжатая версия статуса проекта — только то, что нужно, чтобы Claude в новом окне сразу понимал текущее состояние. Полная история по фазам — в документе проекта «црм » (`claude/crm-mvp-status.md`).

## Что это

Веб-приложение для управления задачами торговых агентов дистрибьютора косметики (Kapous, EPICA, Чистовье, Палитра). Не CRM для сделок — задачник по клиентам-точкам (визиты, продажи, лист ожидания).

**Стек**: Node.js без npm-зависимостей (без Express/React, всё вручную — роутер, multipart, zip), файловая БД `data/db.json` (JSON), scrypt для паролей. Фронтенд — vanilla JS/HTML/CSS, один файл `public/app.js`.

**Рабочая директория текущей сессии** (`/home/claude/crm-project`) — эфемерная песочница, не переживает сессию. Источник правды — переданный пользователю zip-архив и то, что он держит на своём GitHub (деплой на Render через GitHub Desktop).

## Текущий функционал (консолидированно, без фазовой истории)

**Клиенты**: карточка точки (адрес, телефон с WhatsApp-иконкой и нормализацией номера, контактное лицо, тип точки, день визита, статус по договору, способ оплаты, ссылка на 2ГИС, ИНН, мессенджер, удобное время звонка, ЛПР, особые пожелания, окно приёма заявок). Защищённые поля редактирует админ/супервайзер всегда; агент — только если ему явно включено разрешение (чекбокс в «Команде», по умолчанию выключено). Фильтры: день визита, тип точки, «постоянный клиент», задолженность, способ оплаты, «не добрал», «есть акции», текстовый поиск.

**Ассортимент клиента**: регулярный (покупка ≥4 из 7 мес.) и тестовый (1-3 из 7 мес.), с риском отвала (раздел «не добрал», всегда плоский список), остатком на складе (бейдж, срез на дату), группировкой красителей/оксидов в обычном списке (не в «не добрал»). Отдельно — помесячная детализация (`monthlyAssortment`) для фильтра по месяцу в отчётах. «Постоянный клиент» на дашборде теперь считается как «купил 3 календарных месяца подряд» — зависит от ежемесячного архивирования новых данных о продажах через сессию с Claude (кнопки загрузки в интерфейсе нет, решение пользователя).

**Задачи — 3 независимые воронки**:
- «Визиты с супервайзером» (было «Визиты») — В работе → Выполнена (подтверждает супервайзер, этап «Архив») / Не выполнена, теги брендов + Лист ожидания/Прогрев как теги.
- «Воронка продаж» — Звонок → Встреча → Сделка/Провал; закрыть в Сделку/Провал нельзя без аудиозаписи встречи и пояснения (проверка на сервере). Провал выгружается в CSV, опционально — в Google Таблицу (нужна настройка сервисного аккаунта, код готов, но не активирован).
- «Лист ожидания» (новая) — Клиент ждёт товар → Накладная оформлена → Товар получен (подтверждает супервайзер), свои теги брендов.

Даты задач — кастомный виджет ДД.ММ.ГГ (2-значный год), с мини-календарём. Телефон клиента виден на карточках задач во всех воронках. Заявка на перенос даты — если срок уже установлен, агент отправляет заявку, супервайзер одобряет/отклоняет.

**Дашборд**: сводные карточки с фильтром по агенту (клиенты, задачи сегодня, просрочено, риск отвала) и по способу оплаты (долг); карточка риска отвала подсвечивается визуально. Дашборд агента — «Мои показатели» за текущий календарный месяц: продано, клиенты с продажами, звонки/встречи сегодня, топ-10 товаров по каждому бренду (без красителей/оксидов у Kapous/EPICA). Рейтинг клиентов супервайзера (выручка/маржа/активность). Панель «клиенты без задачи на этой неделе», «давно не был», бейджи новых мастеров/точек на подтверждение.

**Календарь**: месяц/неделя/день; встречи супервайзера с клиентом (лёгкая «бронь дня», без этапов) — в дневном виде показывает и агента, и клиента; агент видит только встречи по своим клиентам.

**Отчёты** (супервайзер/администратор): «Ассортимент по агентам» с фильтром по бренду, агенту (с опцией «Все») и месяцу; отдельный отчёт «Акции» с фильтром по агенту. Бейдж «🎁 акции» у клиента в списке + фильтр «Есть акции» видны агенту.

**Прочее**: экспорт клиентов в CSV (только супервайзер), массовая перепривязка клиентов, резервное копирование одной кнопкой (только админ), push-уведомления (только при открытой вкладке, не настоящий web-push), печать маршрута на неделю (супервайзер), «точка закрыта» — запрос агента + подтверждение, журнал заметок по звонкам отдельно от задач.

## Известные ограничения

- Риск отвала и тестовый ассортимент считаются помесячно (не по дням) — приближение.
- Способ оплаты и статус «по договору» — есть не у всех клиентов (нет источника в исходных таблицах).
- Обновление продаж/долгов/остатков/акций — не автоматическое, только через новую сессию с Claude и пересборку архива.
- Бренд товара определяется по ключевым словам/префиксам в названии (EPICA — по префиксу «E », уточнено в последней сессии), не по отдельному столбцу — Палитра осознанно не трогалась.
- На бесплатном тарифе Render данные не гарантированно сохраняются между перезапусками — нужен платный план с постоянным диском; есть кнопка ручного бэкапа.
- Нет смены пароля из интерфейса, нет email/SMS-уведомлений.
- Файловая БД рассчитана на команду до ~10-15 активных пользователей.

## Что заблокировано / ждёт решения пользователя

- Автовыгрузка провалов в Google Таблицу — код готов, нужно вместе с пользователем один раз настроить сервисный аккаунт Google Cloud.

- Два случая совпадения имени клиента между новыми и старыми агентами (Батаева/Жанара/Анастасия vs Нагима/Татьяна/Альбина) — если это разные точки, нужно ручное решение пользователя.
- Партиальные продажи/долги за текущий незакрытый месяц — намеренно не подмешаны в общий расчёт.

## Как работать с этим пользователем

- Присылает правки списком, по одной, ожидая, что каждая будет зафиксирована перед реализацией; даёт финальный сигнал фразой вроде «делай правки» / «делаем» / «всё, я закончил».

- Если в одном вопросе несколько под-пунктов — обычно отвечает свободным текстом только на один; на остальное лучше сделать разумное предположение по умолчанию, явно написать о нём и продолжать, а не переспрашивать бесконечно.
- Деплой — через GitHub Desktop (Clone → скопировать файлы → Commit → Push), инструкции давать по одному шагу, ждать «готово».
- После каждого большого раунда правок: обновить README проекта, обновить статус-документ в проекте «црм », пересобрать zip, проверить чистую установку (импорт с нуля + время запуска), отправить архив.
