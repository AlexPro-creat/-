# Задачник для торговых агентов (дистрибуция косметики)

Веб-приложение для управления визитами торговых агентов к контрагентам (салоны красоты, мед.клиники и т.п.): карточка клиента с данными по маршруту, регулярный ассортимент по продажам, задолженность, доска задач-визитов и вложения (фото/аудио). Работает на телефоне и компьютере через браузер.

Написано на «чистом» Node.js — **без единой внешней библиотеки** (нет ни Express, ни React, ни базы данных вроде Postgres). Это осознанное решение: приложение запускается командой `node src/server.js` без `npm install`, что сильно упрощает установку и последующую поддержку. Все данные хранятся в одном файле `data/db.json` и в папке `data/uploads/` (вложения к задачам).

## Возможности

- **Карточка контрагента**: тип точки, адрес, телефон, контактное лицо, день визита, статус «работает по договору», способ оплаты (нал/безнал/QR), ответственный агент. Эти поля редактирует **только администратор** — торговый агент видит их, но не может менять (кроме заметок).
- **Таблица клиентов**: колонки Название (закреплена слева при горизонтальной прокрутке) → Долг → Ассортимент риск → Открыть → Тип точки → Номер телефона → Контактное лицо; клик по заголовку «Долг» или «Ассортимент риск» сортирует список. Есть быстрый поиск по названию/телефону/контактному лицу.
- **Фильтры по клиентам**: день недели визита, тип точки, только постоянные клиенты (есть регулярный ассортимент), только с задолженностью, «не добрал» (есть товары с риском «отвала» в регулярном ассортименте).
- **Регулярный ассортимент**: список товаров, которые клиент стабильно заказывает (рассчитан по продажам за последние 7 месяцев), отдельным блоком — товары с риском «отвала» (не заказывали в последнем доступном месяце).
- **Тестовый ассортимент**: отдельный список товаров, которые клиент покупал хотя бы раз, но не так регулярно, чтобы попасть в основной ассортимент (разовые/пробные покупки) — виден в карточке клиента и прямо в карточке задачи.
- **Задолженность**: сумма долга и отметка о просрочке — подтягивается из выгрузки по должникам.
- **Доска задач** (воронка визитов): В работе → Выполнена → Не выполнена. Задача сразу создаётся «В работе» (без промежуточного «Новая задача»). У каждой задачи можно проставить теги (Kapous, EPICA, Чистовье, Палитра, новый клиент, Лист ожидания, Прогрев) и отфильтровать доску по ним — «Лист ожидания» и «Прогрев» теперь теги, а не отдельные этапы. Перетаскивание карточек мышью.
- **Срок задачи**: обязателен — без даты задачу не сохранить. Агент задаёт её один раз (при создании); после этого менять срок может только администратор или супервайзер.
- **Отчёт по задаче**: отдельное поле — без заполненного отчёта нельзя перевести задачу в «Выполнена». На карточке задачи заполненный отчёт отмечен зелёной галочкой.
- **Ассортимент в задаче**: из карточки задачи можно раскрыть регулярный (и тестовый) ассортимент клиента, не открывая отдельно его карточку.
- **Календарь**: отдельная вкладка с видами месяц / неделя / день. В мобильной версии на клеточке даты показывается цветная точка с числом незавершённых задач — зелёная, если срок ещё не наступил, красная — если просрочено.
- **История визитов**: по каждому клиенту видно все прошлые задачи с комментариями агента.
- **Вложения к задаче**: фото (скриншоты заказов, накладных) и аудиозаписи прямо в карточке визита.
- **Аватары сотрудников**: администратор может загрузить фото для каждого агента (раздел «Команда») — отображается рядом с именем в списках и на канбане для быстрого узнавания.
- **Роли**:
  - **Администратор** — полный доступ, включая управление сотрудниками и резервное копирование.
  - **Супервайзер** — видит и координирует всех агентов и клиентов; права почти полностью дублируют администратора (редактирование защищённых полей клиента, подтверждение точек, массовая перепривязка, удаление, экспорт CSV, печать маршрута), кроме управления сотрудниками и резервного копирования.
  - **Торговый агент** — видит и работает только со своими клиентами и задачами.
  - **Удаление** клиентов и задач доступно только администратору и супервайзеру — торговые агенты удалять не могут.
- **Новые точки вне маршрута**: если агент добавляет клиента, которого не было в исходной выгрузке, точка помечается «вне маршрута» и «на согласовании» — администратор увидит её на дашборде и подтверждает.
- **Дубли при добавлении клиента**: при создании нового контрагента система проверяет совпадение по названию, адресу и телефону одновременно — если всё совпадает, предупреждает о возможном дубле.
- **Дашборд**: количество клиентов, задачи на сегодня/просроченные, клиенты с риском «отвала» ассортимента, общий долг, новые точки на согласовании; список клиентов на сегодня, список клиентов на сегодня с задолженностью, список просроченных задач, выполнение по каждому агенту (% выполненных визитов), **общее количество задач по всей команде** (карточка «Всего задач по команде» + строка «Итого по команде» в таблице по агентам — видно супервайзеру и администратору), долг в разбивке по каждому агенту, клиенты без задачи на текущую неделю, число заявок на подтверждение (новые точки + закрытие точек).
- **Мой день** (только у торгового агента): упрощённый вид на сегодняшние задачи крупными карточками с кнопками «Позвонить» и «Маршрут» (открывает точку в Google Картах).
- **Клик по номеру телефона** в карточке клиента, таблице клиентов и «Моём дне» сразу открывает звонок на телефоне.
- **Фильтр по способу оплаты** (наличка/перечисление) в таблице клиентов, а также фильтр «показывать закрытые точки».
- **Дата/время создания задачи и автор** — видно администратору и супервайзеру в карточке задачи.
- **Просрочка по дням** — на бейдже задолженности показывается количество дней с даты поставки (из выгрузки по долгам), если дату удалось разобрать.
- **Бейджи в навигации**: на вкладке «Задачи» — число просроченных задач, на вкладке «Клиенты» — число точек, ожидающих подтверждения.
- **Автосоздание следующей задачи**: при первом переводе задачи в «Выполнена», если у клиента указан день визита и нет другой активной задачи в будущем, система сама создаёт следующую задачу на ближайшую подходящую дату.
- **Архив задач**: выполненную задачу должен подтвердить администратор или супервайзер, переведя её в «Архив» — только тогда она пропадает из «Выполнена» у агента (у агента этап «Архив» не отображается вовсе). Массовое удаление задач (с чекбоксами) — доступно только администратору и супервайзеру.
- **Несколько вложений за раз**: к задаче можно прикрепить сразу несколько фото/аудио одним выбором файлов.
- **Заметки по звонкам/контактам** — отдельный от задач лёгкий журнал заметок в карточке клиента (кто и когда оставил).
- **«Точка закрыта»**: агент может отправить запрос на закрытие точки; администратор/супервайзер подтверждает (точка помечается закрытой и её можно скрыть фильтром) или отклоняет, точку всегда можно открыть заново.
- **Дата последнего визита** — видна прямо в карточке клиента; если давно не был у клиента, это дополнительно подсвечено.
- **Экспорт клиентов в CSV** — доступен только супервайзеру.
- **Массовая перепривязка клиентов** к другому агенту (с чекбоксами) — доступна администратору и супервайзеру.
- **Печать маршрута на неделю** (только супервайзер) — кнопка на вкладке «Календарь» формирует список визитов по агентам на текущую неделю и открывает системное окно печати браузера (можно сохранить как PDF средствами браузера).
- **Уведомления о задачах**: при первом входе браузер сразу запрашивает разрешение на уведомления; пока вкладка приложения открыта (в том числе свёрнута/в фоне), система каждые несколько минут проверяет задачи на сегодня/просроченные и присылает уведомление. Это не серверные push-уведомления — при полностью закрытой вкладке/браузере уведомления приходить не будут (см. «Известные ограничения»).
- **Резервная копия одним нажатием** — кнопка «Скачать резервную копию» на вкладке «Команда» (только администратор) скачивает ZIP-архив с базой данных и всеми вложениями.
- **Права супервайзера расширены и во многом дублируют администратора**: супервайзер теперь тоже может редактировать защищённые поля карточки клиента, подтверждать новые точки, подтверждать/отклонять закрытие точек, делать массовую перепривязку клиентов. Управление сотрудниками (создание/удаление пользователей, смена ролей) и резервное копирование остаются только у администратора.

## Новое в Фазе 6

- **Мастера/сотрудники точки**: в карточке клиента — список мастеров (маникюр, парикмахер, стоматолог, массажист и т.п.) с именем, телефоном и специализацией. Агент добавляет мастера сразу (без согласования), новый мастер помечается «новый» до просмотра администратором/супервайзером — счётчик непросмотренных виден на дашборде.
- **6 новых полей в карточке клиента** (редактирует только администратор/супервайзер): ИНН/реквизит, контакт в мессенджере, удобное время звонка, ЛПР (кто принимает решение), особые пожелания, «принимает заявки только в определённое время» (информационное поле, без автоблокировки).
- **Ассортимент теперь с брендом, выручкой и маржой**: в списках регулярного/тестового ассортимента у каждого товара — бренд (Kapous/EPICA/Чистовье/Палитра/Прочее, определяется по названию), сумма продаж и маржа за 7 месяцев. Фильтр по бренду (в т.ч. «Красители/оксиды» одной кнопкой) — удобно готовить предложение по конкретному бренду.
- **Вкладка «Отчёты»** (только супервайзер/администратор): сводная таблица «сколько какого товара продал каждый агент» — товар, бренд, штук, выручка, число клиентов, с тем же фильтром по бренду.
- **Дашборд агента**: «Мои показатели» — продано за 7 мес., клиентов с продажами, звонков/встреч сегодня, выполнено сегодня, просрочено, топ-5 товаров.
- **Дашборд супервайзера дополнен**: задачи на день по команде (выполнено/не выполнено на агента), рейтинг клиентов (выручка/маржа/активные месяцы), счётчик новых мастеров.
- **Воронка продаж «звонок → встреча → сделка/провал»** — отдельная вкладка внутри «Задачи» («Воронка продаж»), независимая от обычной доски визитов. Звонок остаётся открытым до следующего шага, встреча требует аудиозаписи и короткого пояснения — без них задачу нельзя закрыть в «Сделка» или «Провал». Проваленные задачи можно выгрузить в CSV (кнопка/эндпоинт `/api/tasks/failed-export`) и — при настроенном Google-аккаунте — автоматически отправляются строкой в Google Таблицу (см. ниже).
- **Заявка на перенос даты задачи**: агент теперь не «упирается» в заблокированную дату — может отправить заявку с желаемой датой и причиной; администратор/супервайзер одобряет (дата меняется сама) или отклоняет прямо в карточке задачи.
- **Встречи супервайзера с клиентом — в календаре**: у супервайзера в календаре кнопка «+ Встреча с клиентом» (дата/время/заметка); фиолетовая точка в месячном виде и отдельный раздел «👔 Супервайзер» в недельном/дневном виде показывают агентам, какие дни у клиента уже заняты. Удалять встречу может только супервайзер.
- **Обновление остатков/продаж/долгов больше не трогает задачи и другую введённую информацию** — при повторном импорте меняются только расчётные поля (ассортимент, долг), карточка клиента, мастера, заметки и все задачи сохраняются как есть.

### Что нужно от вас, чтобы включить оставшиеся пункты

Часть пунктов из списка требует дополнительных файлов/доступов и пока не подключена:

- **Автовыгрузка «провала» в Google Таблицу** — код готов (`src/googleSheets.js`), но нужен файл ключа сервисного аккаунта Google Cloud и доступ на редактирование к самой таблице; пока не настроено — работает ручной CSV-экспорт без каких-либо действий с вашей стороны.
- **Шаблон загрузки остатков/продаж/долгов/задач через браузер** (без участия Claude между обновлениями) — отложено по вашей явной просьбе, обсудим отдельно, когда решите к этому вернуться.

## Как разместить приложение в интернете, чтобы работала команда

Подробная пошаговая инструкция с прямыми ссылками — в файле **ИНСТРУКЦИЯ_GITHUB_RENDER.md**. Коротко: код заливается на GitHub, а сервис Render.com берёт его оттуда и запускает по постоянной ссылке.

**Важно про данные**: на бесплатном тарифе Render диск не сохраняется постоянно — при обновлении или перезапуске содержимое `data/db.json` и загруженные вложения (`data/uploads/`) может обнулиться. Для реальной работы (когда терять клиентов, задачи и вложения нельзя) нужен платный план Render с постоянным диском (от $7/мес) либо обычный VPS — подключение диска подробно описано в инструкции.

## Обновление данных (продажи, долги, новые контрагенты)

Приложение не подключено напрямую к Google Диску (у него нет доступа/паролей от вашего аккаунта) — обновление происходит вручную, но просто:

1. Загружайте свежие выгрузки в две папки на Google Диске, созданные для этого:
   - **папка для актуальных продаж** — файлы по продажам за новые периоды;
   - **папка для актуальных долгов** — свежая выгрузка по задолженности.
2. Напишите об этом в следующем разговоре с Claude (в этом же проекте на claude.ai) — попросите пересчитать регулярный ассортимент и долги по новым файлам.
3. Claude обновит файлы `data/import/regular_assortment.json`, `data/import/test_assortment.json` и `data/import/debts.json`, вы получите обновлённый архив проекта — залейте его поверх старого на GitHub (см. инструкцию, часть «Что дальше»), Render пересоберёт сайт автоматически.
4. При перезапуске сервер сам подтянет новые данные: новых контрагентов добавит, а вручную исправленные администратором карточки (адрес, телефон, договор и т.п.) не тронет — обновятся только расчётные поля (ассортимент, долг).

## Резервные копии

Все данные — это файл `data/db.json` и папка `data/uploads/`. Периодически скачивайте их с сервера (или, если используете платный диск на Render, делайте снапшот через панель Render) в надёжное место. Потеря `data/db.json` = потеря всех клиентов, задач и истории визитов.

## Структура проекта

```
src/
  server.js    — HTTP-сервер, раздача фронтенда, отдача вложений
  router.js    — минимальный роутер
  db.js        — файловая база данных (JSON)
  auth.js      — пароли (хеширование) и сессии
  api.js       — вся бизнес-логика: клиенты, задачи, вложения, пользователи
  multipart.js — разбор загрузки файлов (фото/аудио)
  import.js    — импорт/обновление контрагентов, ассортимента, долгов при запуске
  miniZip.js   — сборка ZIP-архива для резервной копии (без внешних библиотек)
public/
  index.html, styles.css, app.js  — интерфейс (без сборки, обычный JS)
  sw.js        — минимальный service worker (нужен только для уведомлений в фоне)
data/
  db.json      — все данные приложения (создаётся автоматически)
  uploads/     — загруженные фото/аудио по задачам
  import/      — исходные данные для импорта (контрагенты, регулярный/тестовый ассортимент, долги, остатки, акции)
```

## Известные ограничения MVP

- **«Риск отвала ассортимента» — приближение, а не точный расчёт по дням.** Исходные данные о продажах помесячные (не по датам), поэтому товар помечается «риск», если его не покупали в последнем доступном месяце — это приближение к правилу «не заказывал 14+ дней», а не точный расчёт.
- **«Тестовый ассортимент»** считается по тем же помесячным данным за 7 месяцев — это товары с 1–3 месяцами покупок из 7 (регулярные — от 4 месяцев), а не «купил один раз за всё время работы».
- **Способ оплаты** нужно проставить вручную по каждому клиенту — в исходных таблицах агентов не нашлось отдельного столбца с этими данными.
- **Статус «работает по договору»** заполнен только там, где он был в исходных таблицах (сейчас это данные по точкам Альбины); для остальных клиентов стоит «неизвестно» — уточните и укажите вручную по мере необходимости.
- Обновление продаж/долгов — не автоматическое: см. раздел «Обновление данных» выше.
- Нет смены пароля из интерфейса (пока — через переустановку пользователя администратором).
- **Уведомления о задачах работают, только пока открыта вкладка приложения** (можно свернуть её или переключиться на другое окно — это нормально), но не при полностью закрытом браузере. Настоящие серверные push-уведомления потребовали бы отдельного облачного сервиса и ключей — сознательно не подключали, чтобы не нарушать принцип «ноль внешних зависимостей». Если это критично, можно обсудить подключение позже.
- **«Печать маршрута»** — это системная печать браузера (Ctrl+P / диалог печати), а не готовый файл PDF, который генерирует сервер; чтобы получить PDF-файл, в диалоге печати нужно выбрать «Сохранить как PDF».
- Нет email/SMS-уведомлений о задачах.
- Файловая БД устраивает команду до ~10-15 активных пользователей и умеренного объёма данных; для более серьёзной нагрузки понадобится настоящая СУБД.
- **Бренд товара определяется по ключевым словам в названии** (Kapous/EPICA/Чистовье/Палитра), а не по отдельному столбцу в исходных файлах — в редких случаях товар может попасть в «Прочее», даже если по факту относится к одному из брендов; список ключевых слов можно расширить.
- **Записи встреч (аудио) хранятся на диске сервера** — на бесплатном тарифе Render, как и остальные вложения, они не гарантированно переживают перезапуск (см. раздел «Важно про данные» выше про постоянный диск).
- **Встречи супервайзера — это отдельная лёгкая «бронь дня»**, не полноценная задача: без этапов, отчётов и напоминаний — только видимость в календаре, кто когда занят.
- **Остаток на складе на позиции ассортимента — это срез на дату выгрузки** (25.08.2026), не живая синхронизация со складом; обновляется вручную вместе с остальными данными (см. «Обновление данных» выше). Примерно 11% позиций не находят соответствия в остатках из-за обрезанных до 70 символов названий товаров в исторических файлах продаж — для них бейдж просто не показывается.
- **«Акции» — тоже срез на дату**, не привязаны к конкретной задаче/визиту, показывают только сам факт и количество.
- **Два случая совпадения имени контрагента** между новыми и прежними агентами (нашлось при импорте) не создали вторую карточку — оставлены за прежним агентом; если это на самом деле разные точки с одинаковым названием, скажите — разнесём вручную.
